# Civic Lens エージェント機能 — タスク分解

## 🎯 コアコンセプト
**「市民の怒りを行政への手続きに変換するエージェント」**

市民が漠然と持つ「行政への不満・怒り・不信感」を、**法的根拠ある具体的な手続き**に変換する。
- 怒り → 開示請求
- 不信 → 審査請求
- 不誠実への告発 → 監査請求・陳情・議会質問

---

## 📦 エージェント機能 — 6つのコア機能

### Function 1: 🔍 感情解析 & ペイン抽出
**入力**: 市民の自然言語の「怒り」「不満」記述
**出力**: 構造化された「行政手続としてのアクション」

```
[市民] 「市長の海外視察費用がどうなっているのか知りたい。
        何百万円も使って成果が分からないのは許せない」

[Civic Lens Agent]
   ↓ Gemini 解析
   ↓ Parallel Web Searchで関連情報確認
   ↓ 条例マッチング
   ↓
[エージェント出力]
{
  "identified_pain": "市長の海外視察費用に関する情報隠蔽疑惑",
  "applicable_procedure": "情報公開請求（条例第◯条）",
  "target_authority": "○○市長",
  "specific_documents": [
    "海外視察報告書",
    "出張命令書・復命書",
    "会計伝票・契約関係書類"
  ],
  "legal_basis": "○○市情報公開条例第◯条",
  "next_step": "開示請求書フォーム生成"
}
```

---

### Function 2: 📝 開示請求書 自動生成
**入力**: ペイン抽出結果 + 対象機関情報
**出力**: 自治体の書式に準拠した開示請求書（PDF + テキスト）

```
- 対象機関別の書式に対応（10自治体分）
- 必要記載事項の自動補完
- 対象文書の具体化
- 送付方法・窓口情報の付与
```

---

### Function 3: ⚖️ 審査請求書 自動生成
**入力**: 不開示決定通知書 + 条例情報
**出力**: 審査請求書 + 反論ロジック

```
[不開示決定の理由]：「条例第◯条第◯号該当（法人情報）」

[Civic Lens 分析]
   ↓
[反論ロジック]
- 「法人情報」該当性：本件は法人の競争上の地位を害する情報か？
- 該当条文の解釈：判例では「具体的かつ実質的な害益」が必要
- 類似の開示事例：○○市では同種事案で開示
- 部分開示可能性：黒塗り処理で対応可能
```

---

### Function 4: 📚 判例・先例 自動調査（Parallel Web Search活用）
**入力**: 検索キーワード（条例条項、テーマ）
**出力**: 関連判例・開示例のリスト + 抜粋 + URL

```
例: 「海外視察 費用 情報開示」

[Parallel Web Search]
   ↓
[検索結果]
- 最高裁判例 ○○（URL）
- ○○市開示事例（URL）
- 総務省ガイドライン（URL）
- 学術論文（URL）
```

---

### Function 5: 📅 期限管理ダッシュボード
**入力**: 申請イベント
**出力**: 期限通知 + 残日数表示

```
- 60日ルール（処分庁の開示決定期間）
- 延長通知の期限
- 審査請求の期限（3ヶ月）
- 議会陳情の締切
```

---

### Function 6: 🏛️ 多様な対抗手段への展開
**入力**: 案件タイプ
**出力**: 最適な対抗手段の提案

```
[対抗手段ライブラリ]
- 情報公開請求（基本）
- 審査請求（不開示決定後）
- 監査請求（財務会計行為）
- 議会陳情・請願
- 個人情報の開示（自分の情報）
- オンブズマン活動
```

## 🚀 推奨トラック：Parallel + Grafana（複数技術組み合わせ戦略）

実は ハッカソン規約 を確認すると、**1つのパートナートラックに絞る必要**があるかもしれません。
- 安全策：**Parallel** 単独で提出
- 拡張案：Parallel を主軸、Grafana で可視化

Parallel の `search.parallel.ai/mcp` は：
- ✅ Streamable HTTP で接続可能
- ✅ APIキー不要（Free tier）
- ✅ Gemini CLI から直接使える
- ✅ 条例・判例調査に最適
